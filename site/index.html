A generator-first platform, not a SaaS you rent

The hugmesh-generator repo builds hardened OS images for every cluster role and provisions everything from a single FAT32 KEYS USB partition at first boot. Once the cluster is up, you manage it entirely through role-gated UIs and BFF APIs — no direct cluster access required after day one.

Frontend

Angular micro-frontends, loaded at runtime via native federation. Login, user, mod, admin, Matrix, fediverse, forum, wiki, video, games — each its own deployable remote, greyed out automatically when a service isn't installed.

Backend

Spring WebFlux BFFs, one per surface, each scoped to exactly what its role needs. A single Spring Cloud Gateway validates every request and enforces a data-driven, per-brand route-access policy before anything reaches a service.

Identity & control plane

Casdoor as the OIDC IdP behind a native login flow — the browser never sees a redirect or a raw token, only an opaque session cookie. Cassandra, Vault, and a private mesh network round out the control plane.

Multi-tenant by design

One deployment, many brands. Each tenant gets its own namespace, mTLS boundary, identity issuer, and role hierarchy — provisioned at runtime through the superadmin Service Catalog, no redeploy required.

Everything is source. Everything ships as a release.

Every service in the platform is a separate repository with its own build, its own release workflow, and its own container image or binary artifact. Start with the generator if you're standing up a cluster; browse the rest if you're contributing to a specific service.
